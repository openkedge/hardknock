# V0.22 distributed sync checkpoint

This is a partial V0.22 implementation. It builds on the V0.7 federation package
exchange and the completed V0.21 team layer. It does not satisfy the full V0.22
definition of done or the flagship end-to-end demo.

## Implemented

- Reuses the V0.7 Ed25519 node identity and detached signing. Node identity remains
  separate from local peer trust, environment context, and execution authority.
- Adds `HardknockNode`, `EnvironmentIdentity`, protocol capabilities, publish and
  receive policies, peer trust dimensions, and a local filesystem endpoint model.
- Adds immutable revisioned `SyncArtifact` metadata, content hashes, signed
  `hardknock.sync.v1` envelopes, sender/nonces, root-origin and relay fields, and
  a separate remote knowledge lifecycle.
- Adds schema 30 for node metadata, configured peers, cursors, sessions, envelopes,
  artifacts, receipt paths, remote records, contradictions, revocations,
  reproduction requests, manifests, and append-only sync events. Local Lessons and
  hierarchy rows are not overwritten by import.
- Adds a network-free filesystem transport, cursor-based pull, session history,
  replay rejection, artifact deduplication, and qualitative environment comparison.
- Direct-origin signed knowledge imports as advisory or reproduction required.
  Incompatible or unverified relay material is quarantined. Critical Constraints
  and remote exceptions do not gain local mutation authority.
- Adds signed origin revocations, explicit origin-compromise review marking, and
  independent local support preservation while withdrawing revoked origin advice.
- Adds CLI `node show|identity|environment`, `sync pull|push|status|history|inspect`,
  and a remote reproduction queue command under `federate reproduce`.
- `peer add --sync-dir PATH` configures a filesystem sync endpoint; peer trust,
  block, and removal commands update its sync configuration.
- Adds a reusable isolated multi-node test harness and 23 deterministic distributed
  tests covering the implemented receive and trust boundaries.

## Trust boundary and limitations

A relay envelope authenticates its sender, not the alleged root origin. This
checkpoint quarantines a new relay artifact until an origin-authenticated path is
available; it does not implement a portable origin signature chain yet. Key
revision 1 is supported; rotation and compromised-key notices are deferred.

`support_remote_artifact` checks stored supporting evidence paths and their exact
remote-artifact reference for noncritical artifacts. Critical Constraints and
exceptions remain closed to this generic path until controlled local reproduction
and local knowledge-revision creation are integrated. Existing V0.7 local
reproduction remains available for its supported portable Lesson flow; the new sync
record is not yet connected to it.

The current `sync push` accepts an already signed envelope supplied by a trusted
local operator; automatic artifact selection, publication redaction, and envelope
generation from the local experience store are not implemented. The new CLI has no
HTTP transport or passive registry. The filesystem cursor is a filename position,
not a distributed event log. Sync does not yet alter runtime decisions, plan state,
team knowledge delivery, or active assurance. The plan, economics, and epistemic
tests currently exercise conservative pure decision functions, not complete
cross-component execution.

Remaining V0.22 work includes origin-authenticated multi-hop relay and revocation
propagation, controlled reproduction and scoped local promotion, actual
runtime/plan/team/economics integration, key rotation, redaction of new publication
payloads, a complete 24-fixture integration suite, and the comparative benchmark.

## Verification

The distributed suite passes 23 tests with no failures. The full offline test run
passes 452 tests, with 5 ignored and no failures across 35 test binaries. Formatting,
Clippy, and CLI smoke checks also pass.
