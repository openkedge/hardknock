# V0.22 distributed sync checkpoint

This is a partial V0.22 implementation. It builds on the V0.7 federation package
exchange and the completed V0.21 team layer. It does not satisfy the full V0.22
definition of done or the flagship end-to-end demo.

## Implemented

- Reuses the V0.7 Ed25519 node identity and detached signing. Node identity remains
  separate from local peer trust, environment context, and execution authority.
- Adds `HardknockNode`, `EnvironmentIdentity`, protocol capabilities, publish and
  receive policies, peer trust dimensions, and a local filesystem endpoint model.
- Adds immutable revisioned `SyncArtifact` metadata, content hashes, signed
  `hardknock.sync.v1` envelopes, sender/nonces, root-origin and relay fields, and
  a separate remote knowledge lifecycle.
- Adds schema 30 for node metadata, configured peers, cursors, sessions, envelopes,
  artifacts, receipt paths, remote records, contradictions, revocations,
  reproduction requests, manifests, and append-only sync events. Local Lessons and
  hierarchy rows are not overwritten by import.
- Adds a network-free filesystem transport, cursor-based pull, session history,
  replay rejection, artifact deduplication, and qualitative environment comparison.
- Direct-origin signed knowledge imports as advisory or reproduction required.
  Incompatible or unverified relay material is quarantined. Critical Constraints
  and remote exceptions do not gain local mutation authority.
- Adds signed origin revocations, explicit origin-compromise review marking, and
  independent local support preservation while withdrawing revoked origin advice.
- Adds `sync revoke PEER HASH --reason REASON`, signed revocation propagation
  through pull and trusted relays, and pending revocation handling when the
  control message arrives before its target. A revoked imported Lesson bundle
  leaves federation search and cannot be newly reproduced or promoted; existing
  independent local reproduction remains recorded for review.
- Adds CLI `node show|identity|environment`, `sync pull|push|status|history|inspect`,
  and a remote reproduction queue command under `federate reproduce`.
- Adds `sync publish PEER --lesson LESSON` for a locally validated Lesson. It
  reuses V0.7 publication policy and redaction, then signs a sync artifact and
  envelope. `sync import HASH` passes a verified advisory Lesson into the
  existing local federation reproduction flow. `sync relay PEER HASH` forwards
  only non-revoked evidence with an origin signature.
- Publication reuses the signed envelope for the same Lesson revision, so a
  retry does not create a second artifact. Filesystem pulls select the configured
  sender even when several nodes use the same directory.
- An origin signature over immutable artifact content survives relay. A receiver
  requires a configured, trusted origin key before admitting a relayed artifact
  as advisory; otherwise it quarantines the copy. Relay path labels alone do
  not establish authenticity.
- `peer add --sync-dir PATH` configures a filesystem sync endpoint; peer trust,
  block, and removal commands update its sync configuration.
- Adds a reusable isolated multi-node test harness and 28 deterministic distributed
  tests covering the implemented receive and trust boundaries, plus an end-to-end
  CLI test for publication, pull, import, reproduction, and relay.

## Trust boundary and limitations

A relay envelope authenticates its sender, while the embedded origin signature
authenticates that origin's content claim. It does not authenticate every
intermediate hop or independently prove the asserted root evidence. Key
revision 1 is supported; rotation and compromised-key notices are deferred.

`support_remote_artifact` checks stored supporting evidence paths and their exact
remote-artifact reference for noncritical artifacts. Critical Constraints and
exceptions remain closed to this generic path until controlled local reproduction
and local knowledge-revision creation are integrated. Synced portable Lessons now
enter the existing V0.7 import and reproduction flow through `sync import`; this
does not itself promote the sync record or authorize a critical action.

`sync push` still accepts an already signed envelope supplied by a trusted
local operator. `sync publish` explicitly selects one validated Lesson; it does
not schedule publication or cover all artifact types. The new CLI has no
HTTP transport or passive registry. The filesystem cursor is a filename position,
not a distributed event log. Sync does not yet alter runtime decisions, plan state,
team knowledge delivery, or active assurance. The plan, economics, and epistemic
tests currently exercise conservative pure decision functions, not complete
cross-component execution.

Remaining V0.22 work includes controlled local promotion for critical Constraints
and exceptions, actual runtime/plan/team/economics integration, key rotation,
broader artifact publication, full transport and
failure-mode integration coverage, and the comparative benchmark.

## Verification

The distributed suite passes 28 tests. The federation CLI test exercises
three local nodes, publication, pull, local reproduction, relay, and signed
revocation propagation. The full offline all-target suite passes serially, with
the optional/manual tests ignored.
Formatting and all-target/all-feature Clippy with warnings denied also pass.
