# V0.18 Pass 2 implementation report

Validation results and benchmark measurements are recorded below. All correctness claims concern the deterministic local fixtures.

1. **Files:** added `src/knowledge_runtime/{model,context,resolution,health,conflict,guard,mod}.rs`, `src/store/knowledge_runtime.rs`, `src/cli/guard_candidate.rs`, migration 023, `tests/runtime_knowledge.rs` and four integration documents. Extended hierarchy persistence, runtime model/controller/store, bridge/protocol, development bundle, effect commit, CLI, assurance subject handling, curriculum goals/execution events and regression tests. Pass 1 files remain part of the working-tree change.
2. **Migration:** 023 adds immutable hierarchy/artifact revisions, snapshots, resolution records, applications, conflicts, health events, context observations, Guard candidates and dependencies. JSON aggregates reuse the existing persistence style.
3. **Context mapping:** task family, runtime, platform, normalized action and effect are observed; provider/API/resource/token and other structured dimensions use supplied typed observations.
4. **Trust:** attestation > effect adapter > runtime > adapter > user > agent > imported. Only adapter-or-higher values activate scopes. Agent RPC reports cannot choose their source.
5. **Conflicts:** retain all reported values; select the strongest consistent value. Equal strongest disagreement yields unknown.
6. **Resolver:** one shared service snapshots, applies health projection, invokes Pass 1 resolution and projects operational references.
7. **Bundle:** extended the existing development bundle with optional hierarchy guidance. Configurable per-category counts; display statements and lineage are bounded independently from the complete audit record.
8. **Constraints:** applicable operational Constraints recommend REPLAN. They are not PolicyBlock authority.
9. **AntiPatterns:** applicable AntiPatterns recommend REPLAN; ancestor warning deduplication is preserved.
10. **Recovery:** matching explicitly pinned executable Recovery yields RECOVER; a parent without a procedure remains guidance.
11. **Runtime conflicts:** safe/testable low-risk conflict yields EXPERIMENT; otherwise approval. No winner is silently selected.
12. **Snapshot:** identifies immutable hierarchy and artifact revisions and the resolver policy/version.
13. **Immutability:** database triggers reject historical updates/deletes; content hashes and revision registration reject content replacement.
14. **References:** common `KnowledgeRevisionRef` preserves artifact kind, identity and revision. Separate hierarchy refs include content hashes.
15. **Resolution record:** persists trusted context/hash, conflict observations, applied/suppressed/unknown references and full ordered trace.
16. **History:** historical resolution reads archived hierarchy state and captured policy, and replay checks it against recorded knowledge.
17. **Comparison:** current hypothetical evaluation holds the old context fixed, displays current knowledge and writes no new decision.
18. **TOCTOU:** exact action/session binding, current hierarchy hashes and refreshed authoritative context are checked before effect commit. Repeated action IDs cannot reuse hierarchy guidance. Remote atomicity remains the effect adapter's responsibility.
19. **Health:** invalid parents invalidate purely inherited child support in a deterministic projection; health changes are persisted with hierarchy saves.
20. **Independent children:** distinct supporting evidence keeps an independently supported child eligible. Mixed support is preserved conservatively as independent support remains.
21. **Conflict planning:** explicit paired ExperimentRequest templates require a concrete evaluator and fit the existing budget; missing templates preserve conflict.
22. **Curriculum:** `--skill` compiles the plan into a persisted existing Curriculum with Experiment trials. It requires a real registered Skill.
23. **Economics:** conflict planning creates existing opportunities using exposure, severity, mitigation gap and decision relevance. Existing debt reporting surfaces frequently exposed override gaps.
24. **Guard candidate:** source Guard/revision, source knowledge, reason, proposed change, evidence, status and timestamp.
25. **Manifest:** reuses V0.11 EvidenceManifest with a hierarchy/scope/reference wrapper and hash. Hash verification is integrity checking, not independent evidence attestation.
26. **Handoff:** local JSON export and verify commands; no external API is called.
27. **Authority:** Guard enforcement remains unchanged. Local insertion cannot self-assign external acceptance.
28. **Adapters:** Claude, Codex, Hermes and shell share normalized bridge/controller resolution. A bridge regression verifies consistent bundles and report trust. Native adapters retain their existing translated response formats.
29. **Why:** existing `why` prints snapshot and resolution steps; JSON includes the complete structured knowledge result.
30. **CLI:** resolve, explain, audit, hierarchy import/show/validate, snapshots show/diff, conflicts list/show/plan, readonly decision replay and Guard generate/list/show/export/verify.
31. **Idempotency:** trusted valid token activates the exception; expired or unknown token retains the general Constraint.
32. **Stale/unknown:** stale, contradicted and retired exceptions cannot weaken the parent. Missing and conflicting authoritative values remain conservative.
33. **Policy:** external approval still requires approval after a valid learned exception; hard policy still blocks.
34. **Replay:** old no-exception REPLAN remains historically reproducible after a new exception permits hypothetical ACT. No original record changes. Runtime persistence also rejects tampered operational projections even when the caller recomputes the outer record hash.
35. **TOCTOU tests:** hierarchy changes, authoritative token changes and wrong action identity are rejected.
36. **Experiment:** real local paired shell candidates run through ExperimentOrchestrator; a stored Controlled result supports explicit narrower scope revision. A real curriculum is persisted from the plan.
37. **Guard tests:** new Constraint, exception, contradiction review, dependency notification, export/verify and tamper rejection; external acceptance assignment rejected.
38. **Exception harm prevention:** lifecycle/token matrix checks zero invalid activations over nine evaluated cases and zero stale escape over one applicable stale attempt. This is prevention, not an empirical provider failure-rate estimate.
39. **Parent tests:** inherited support is invalidated; independently supported child survives. Runtime benchmark covers independent parent invalidation.
40. **Dedup:** AntiPattern child yields one warning with ancestor lineage.
41. **Performance:** see measured validation section below. Context construction, combined retrieval/resolution/bundle time and controller time are measured; no production latency claim.
42. **Storage:** unchanged knowledge deduplicates snapshots. Measurements count snapshot JSON separately from archived revisions and decision/resolution history.
43. **Ablation:** fixture flat top-three applicable warnings versus naive most-specific match ignoring lifecycle/exception validation versus full hierarchy. This is a controlled fixture ablation, not a benchmark of all legacy retrieval heuristics.
44. **Limitations:** imported opaque artifact IDs may have reference-only guidance; executable Recovery must be registered explicitly. Causal/diversity mechanism selection is explicit. Scope interpretation and application outcome attribution require caller review; experiment IDs are checked, but arbitrary shell outputs are not machine-interpreted as scope proofs. Cross-system atomicity and real provider token semantics are not established by local fixtures. No repeated-failure workload or production dataset was run.
45. **Deviations:** snapshots support several independent hierarchies; aggregate JSON stores traces/references instead of redundant per-step tables; the established context bundle contains a `knowledge` section instead of introducing a second identically named bundle; plans compile via existing Skill curricula rather than introducing a new executor. These choices preserve existing architecture and semantics.

## Validation and measurements

- Full suite with local socket/process access: **326 passed, 0 failed, 4 ignored**. Initial sandbox run failed only local socket/process tests; the host rerun passed all suites.
- After the final integrity changes, runtime, hierarchy-runtime, bridge and curriculum suites: **58 passed, 0 failed, 1 ignored**. This includes 20 runtime-knowledge tests, the API-v3 boundary/negative-control demo, and tampered-projection rejection.
- Final `cargo fmt --check`, `git diff --check`, and `cargo clippy --all-targets --all-features -- -D warnings`: **passed**. Offline builds used the installed Rust toolchain; debug/incremental output was reduced to stay within local disk capacity.
- Explicit manual runtime benchmark: **9/9** full-hierarchy decisions correct, **7/9** flat and **7/9** naive. Incorrect allows: **0 / 0 / 2** for hierarchy/flat/naive. Unnecessary interventions: **0 / 1 / 0**.
- Eight requested families plus expired-token variant; one sibling-conflict fixture surfaced. Nine lifecycle/token cases: **0/9 invalid exception activations**. Applicable stale override: **0/1 escapes**.
- P95 measured tuple (total / context build / combined retrieval-resolution-bundle / controller): **1,854 / 6 / 1,797 / 20 microseconds**, 50 warm-store iterations. Tuple selected by total latency, not independent per-stage percentiles.
- Snapshot reuse: **1 snapshot**, **1,034 JSON bytes**, **5 artifact refs** across 50 contexts. Separate resolution/decision audit rows grow per decision. No large-scale storage or repeated-failure workload was measured.
- Flat and naive arms are explicitly defined local ablations. Decision correctness is measured; identical decisions do not prove identical selected knowledge. Separate identity/dedup and replay tests cover those semantics.
