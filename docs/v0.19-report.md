## Scope and limitations

The primitive state evaluator is intentionally conservative: unsupported conditions and unavailable external observations remain unknown. Arbitrary schemas, live process snapshots, distributed atomicity and production effect commits are not supplied by this layer. Container execution needs a compatible installed runtime and tools; the verified local tests use the explicitly selected host provider and report Observed assurance.

Recovery selection is explicit. Recovery plans do not create a second automatic retry scheduler. A sequence of successful normal Tools is insufficient to claim recovery coverage. Promotion requires actual recovery outcomes for failure-point trials; this pass does not claim every fixture is a validated CompositeSkill. The Guard export path therefore refuses under-supported invariants.

Distinct evaluator specifications still share the primitive evaluator implementation. They do not establish independent implementation fault domains. Common dependencies are retained in the existing epistemic representation. Controlled state injections describe the local model only; they do not certify a production fault injection.

The comparative baseline checks current component registration/pinning, not a freshly retrained population of independently hardened components. Results demonstrate the mechanism on declared fixtures; they do not estimate production failure rates. No numeric superiority claim should be inferred beyond these cases.

## Deviations and rationale

The composition coordinator reuses Realities, ToolRouter, capability policy, cancellation and attestations directly rather than flattening the sequence into an ExperimentOrchestrator shell candidate. Flattening would merge workspaces and lose per-step isolation and runtime resolutions. Curriculum dispatch uses this same coordinator and the existing curriculum lifecycle.

CLI failure injections are typed request files rather than separate shorthand perturbation flags. This preserves step identity, values and evaluator details in replayable input. EffectPlan references can be archived and inspected, but trial execution refuses to grant them external commit authority. Unsupported Recovery actions require an explicit Tool binding.

V0.20 long-horizon planning remains outside this milestone.

## Validation

- `cargo test --offline --all-targets --all-features -- --test-threads=1`: **353 passed, 0 failed, 5 ignored**.
- After the final procedure-wrapper cleanup: composition, tools and runtime-knowledge regression suites: **58 passed, 0 failed, 2 ignored**.
- Explicit comparative benchmark: **1 passed**, five actual step invocations and zero production commits. Current-component-only checks detected 0/3 adverse cases; static preflight detected the capability flow (1/3); full composition validation detected all three. Credential/capacity execution took 687/433 ms; capability admission rejected before any step ran.
- Preflight timing samples for 10/25/50 steps: **422 / 1,809 / 13,146 μs**. These are engineering samples on the local machine, not percentile or statistical claims.
- `cargo fmt --all --check` and `git diff --check`: clean.
- `cargo clippy --offline --all-targets --all-features -- -D warnings`: clean.
- CLI `compose --help` exposes all documented commands.

The first parallel full-suite run failed the existing Bridge p95 latency assertion (69,016 μs versus a 25 ms threshold). The serial full-suite run passed that test without changing its threshold. The separate benchmark and ignored performance test were run explicitly; other opt-in integration tests remain ignored.
